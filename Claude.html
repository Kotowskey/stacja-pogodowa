MQTT z szyfrowaniem ESP32 ↔ Raspberry Pi 4

Najwygodniejsze rozwiązanie to TLS/SSL na brokerze Mosquitto z certyfikatami. Poniżej kompletny schemat.

Architektura

ESP32  ──TLS──►  Mosquitto (RPi4)  ◄──TLS──  klienty HA / Python

1. Raspberry Pi – konfiguracja Mosquitto z TLS

Generowanie certyfikatów (self-signed CA)
bash
mkdir -p ~/mqtt-certs && cd ~/mqtt-certs

# CA
openssl genrsa -out ca.key 2048
openssl req -new -x509 -days 3650 -key ca.key -out ca.crt \
  -subj "/CN=MQTT-CA"

# Serwer (broker)
openssl genrsa -out server.key 2048
openssl req -new -key server.key -out server.csr \
  -subj "/CN=raspberrypi.local"
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key \
  -CAcreateserial -out server.crt -days 3650

# Kopiuj do Mosquitto
sudo cp ca.crt server.crt server.key /etc/mosquitto/certs/
sudo chown mosquitto: /etc/mosquitto/certs/*
/etc/mosquitto/conf.d/tls.conf
ini
listener 8883
cafile   /etc/mosquitto/certs/ca.crt
certfile /etc/mosquitto/certs/server.crt
keyfile  /etc/mosquitto/certs/server.key

# Opcje bezpieczeństwa
tls_version tlsv1.2
require_certificate false   # true = mTLS (klient też ma certyfikat)

# Uwierzytelnianie hasłem (zalecane obok TLS)
allow_anonymous false
password_file /etc/mosquitto/passwd
bash
sudo mosquitto_passwd -c /etc/mosquitto/passwd esp32_user
sudo systemctl restart mosquitto

2. ESP32 – klient z TLS (Arduino/ESP-IDF)

Jedyne co musisz dostarczyć na ESP32 to certyfikat CA (wbudowany w firmware).

Sposób A – WiFiClientSecure + PubSubClient
cpp
#include <WiFiClientSecure.h>
#include <PubSubClient.h>

// Wklej zawartość ca.crt (skopiuj z RPi)
const char* CA_CERT = R"EOF(
-----BEGIN CERTIFICATE-----
MIIDXTCCAkWgAwIBAgIJAP...
-----END CERTIFICATE-----
)EOF";

WiFiClientSecure wifiClient;
PubSubClient mqttClient(wifiClient);

void setup() {
    WiFi.begin(SSID, PASSWORD);
    while (WiFi.status() != WL_CONNECTED) delay(500);

    wifiClient.setCACert(CA_CERT);
    // wifiClient.setInsecure(); // TYLKO do testów – wyłącza weryfikację!

    mqttClient.setServer("raspberrypi.local", 8883);
    mqttClient.setBufferSize(512);

    while (!mqttClient.connected()) {
        mqttClient.connect("esp32-device", "esp32_user", "haslo");
        delay(1000);
    }
}

void loop() {
    mqttClient.loop();
    mqttClient.publish("sensors/temp", "23.5");
    delay(5000);
}
Sposób B – ESP-IDF (esp-mqtt component)
c
esp_mqtt_client_config_t mqtt_cfg = {
    .broker = {
        .address.uri      = "mqtts://raspberrypi.local:8883",
        .verification.certificate = CA_CERT,  // PEM jako const char*
    },
    .credentials = {
        .username = "esp32_user",
        .authentication.password = "haslo",
    },
};
esp_mqtt_client_handle_t client = esp_mqtt_client_init(&mqtt_cfg);
esp_mqtt_client_start(client);

3. Jak wgrać certyfikat CA na ESP32

Opcja 1 – hardcode w kodzie (najprostsze): wklej PEM jako const char* jak wyżej.

Opcja 2 – plik w SPIFFS/LittleFS (wygodne przy rotacji certyfikatów):

cpp
// Odczyt z filesystem
File f = LittleFS.open("/ca.crt", "r");
String cert = f.readString();
wifiClient.setCACert(cert.c_str());

Opcja 3 – NVS (produkcyjne, bezpieczne): certyfikat i dane logowania w Non-Volatile Storage, flashowane osobno.

4. Weryfikacja połączenia

bash
# Na RPi – sprawdź czy TLS działa
mosquitto_sub -h localhost -p 8883 \
  --cafile ~/mqtt-certs/ca.crt \
  -u esp32_user -P haslo \
  -t "sensors/#" -v

# Test z openssl
openssl s_client -connect raspberrypi.local:8883 -CAfile ~/mqtt-certs/ca.crt

Instrukcja konfiguracji MQTT z TLS na Raspberry Pi 4

Punkt 0 – Prompt dla AI z dostępem do kodu

Prompt dla AI:

Skonfiguruj broker MQTT Mosquitto z szyfrowaniem TLS na Raspberry Pi 4 z Raspberry Pi OS (Debian-based). Wykonaj następujące kroki:

  1. Zainstaluj Mosquitto i mosquitto-clients przez apt.
  2. Wygeneruj self-signed PKI (CA → certyfikat serwera) używając openssl w katalogu ~/mqtt-certs. CN dla CA ustaw na MQTT-CA, CN dla serwera na raspberrypi.local. Wszystkie certyfikaty ważne 10 lat.
  3. Skopiuj ca.crt, server.crt, server.key do /etc/mosquitto/certs/ i ustaw właściciela na użytkownika mosquitto.
  4. Utwórz plik konfiguracyjny /etc/mosquitto/conf.d/tls.conf z listenerem na porcie 8883, wskazaniem na wygenerowane pliki, wersją TLS 1.2, wyłączonym anonymous access i plikiem haseł /etc/mosquitto/passwd.
  5. Utwórz użytkownika MQTT esp32_user z hasłem TWOJE_HASLO używając mosquitto_passwd.
  6. Zrestartuj Mosquitto i sprawdź status usługi.
  7. Przetestuj połączenie lokalnie przez mosquitto_sub i mosquitto_pub z flagą --cafile.
  8. Wyświetl zawartość ca.crt w formacie PEM – będzie potrzebna do wgrania na ESP32.

Jeśli któryś krok się nie powiedzie, wyświetl pełny błąd i zaproponuj diagnozę.

Krok 1 – Aktualizacja systemu i instalacja Mosquitto

bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y mosquitto mosquitto-clients openssl

Sprawdź czy usługa wystartowała:

bash
sudo systemctl status mosquitto

Oczekiwany wynik: Active: active (running). Mosquitto domyślnie nasłuchuje na porcie 1883 (nieszyfrowanym) – zmienisz to w kolejnych krokach.

Krok 2 – Utworzenie struktury katalogów na certyfikaty

bash
mkdir -p ~/mqtt-certs
cd ~/mqtt-certs

Wszystkie pliki kluczy i certyfikatów będą tymczasowo tu generowane, zanim trafią do Mosquitto.

Krok 3 – Generowanie CA (Certificate Authority)

CA to twój własny "urząd certyfikacji" – podpisze certyfikat serwera, a ESP32 będzie mu ufać.

bash
# Klucz prywatny CA
openssl genrsa -out ca.key 2048

# Certyfikat CA (self-signed, ważny 10 lat)
openssl req -new -x509 -days 3650 \
  -key ca.key \
  -out ca.crt \
  -subj "/CN=MQTT-CA/O=HomeNet/C=PL"

Weryfikacja:

bash
openssl x509 -in ca.crt -text -noout | grep -E "CN|Not After"

Krok 4 – Generowanie certyfikatu serwera (brokera)

bash
# Klucz prywatny serwera
openssl genrsa -out server.key 2048

# CSR – Certificate Signing Request
openssl req -new \
  -key server.key \
  -out server.csr \
  -subj "/CN=raspberrypi.local/O=HomeNet/C=PL"

# Podpisanie przez CA
openssl x509 -req \
  -in server.csr \
  -CA ca.crt \
  -CAkey ca.key \
  -CAcreateserial \
  -out server.crt \
  -days 3650

⚠️ Ważne: Jeśli łączysz się z ESP32 podając IP zamiast raspberrypi.local, musisz dodać SAN (Subject Alternative Name). Zamiast powyższego podpisania użyj:

bash
# Utwórz plik z rozszerzeniami
cat > san.cnf << EOF
[req]
distinguished_name = req_distinguished_name
[req_distinguished_name]
[v3_req]
subjectAltName = @alt_names
[alt_names]
DNS.1 = raspberrypi.local
IP.1  = 192.168.1.100
EOF

openssl x509 -req \
  -in server.csr \
  -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out server.crt -days 3650 \
  -extfile san.cnf -extensions v3_req

Zastąp 192.168.1.100 rzeczywistym IP Raspberry Pi.

Weryfikacja łańcucha:

bash
openssl verify -CAfile ca.crt server.crt
# Oczekiwane: server.crt: OK

Krok 5 – Instalacja certyfikatów dla Mosquitto

bash
# Utwórz katalog jeśli nie istnieje
sudo mkdir -p /etc/mosquitto/certs

# Kopiuj pliki
sudo cp ca.crt server.crt server.key /etc/mosquitto/certs/

# Ustaw właściciela i uprawnienia
sudo chown mosquitto:mosquitto /etc/mosquitto/certs/*
sudo chmod 640 /etc/mosquitto/certs/*

Sprawdzenie:

bash

# Oczekiwane: właściciel mosquitto, prawa -rw-r-----

Krok 6 – Konfiguracja Mosquitto TLS

bash
sudo nano /etc/mosquitto/conf.d/tls.conf

Wklej:

ini

listener 8883
cafile   /etc/mosquitto/certs/ca.crt
certfile /etc/mosquitto/certs/server.crt
keyfile  /etc/mosquitto/certs/server.key

# Minimalna wersja TLS

Ostatni blok jest opcjonalny – przydatny gdy Home Assistant działa lokalnie na tym samym RPi i nie potrzebuje TLS do połączenia z brokerem.

Konfiguracja TLS MQTT na ESP32 – Arduino IDE

Punkt 0 – Prompt dla AI z dostępem do kodu

Prompt dla AI:

Skonfiguruj klienta MQTT z TLS na ESP32 w Arduino IDE (C++). Wykonaj następujące kroki:

  1. Zainstaluj biblioteki PubSubClient (Nick O'Leary) i WiFiClientSecure (wbudowana w ESP32 core) przez Arduino Library Manager.
  2. Utwórz plik secrets.h z danymi WiFi, danymi logowania MQTT oraz certyfikatem CA w formacie PEM jako const char*.
  3. W pliku głównym .ino skonfiguruj WiFiClientSecure z certyfikatem CA, następnie PubSubClient na port 8883.
  4. Zaimplementuj funkcje: connectWiFi(), connectMQTT() z logiką reconnect, callback dla wiadomości przychodzących, oraz loop() publikujący dane co 5 sekund.
  5. Dodaj obsługę błędów TLS – wypisuj kod błędu przez Serial gdy połączenie się nie powiedzie.
  6. Skompiluj i wgraj na ESP32. Zweryfikuj w Serial Monitorze (115200 baud) że pojawia się Connected to MQTT broker (TLS).

Używaj Arduino ESP32 core w wersji 2.x lub 3.x. Nie używaj setInsecure() – weryfikacja certyfikatu ma być włączona.

MIIDXTCCAkWgAwIBAgIJAP7pWDkNTmomMA0GCSqGSIb3DQEBCwUAMEExCzAJBgNV
BAYTAlBMMRAwDgYDVQQKDAdIb21lTmV0MRAwDgYDVQQDDAdNUVRULUNBMB4XDTIz

Krok 5 – Główny plik MqttTLS.ino

cpp
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <PubSubClient.h>
#include "secrets.h"

// ── Topiki MQTT ───────────────────────────────────────────
#define TOPIC_PUB   "esp32/sensors/temperature"
#define TOPIC_SUB   "esp32/commands/#"

// ── Obiekty globalne ──────────────────────────────────────
WiFiClientSecure  tlsClient;
PubSubClient      mqttClient(tlsClient);

// ── Timery ────────────────────────────────────────────────
unsigned long lastPublishMs   = 0;
const long    publishInterval = 5000;   // ms

// ─────────────────────────────────────────────────────────
// Callback – wywoływany przy odebranej wiadomości
// ─────────────────────────────────────────────────────────
void onMessageReceived(char* topic, byte* payload, unsigned int length) {
    Serial.print("[MQTT] Odebrano na topiku: ");
    Serial.println(topic);

    // Konwersja payload na String
    String message;
    message.reserve(length);
    for (unsigned int i = 0; i < length; i++) {
        message += (char)payload[i];
    }
    Serial.print("[MQTT] Wiadomość: ");
    Serial.println(message);

    // ── Obsługa komend ────────────────────────────────────
    if (String(topic) == "esp32/commands/led") {
        if (message == "ON")  digitalWrite(LED_BUILTIN, HIGH);
        if (message == "OFF") digitalWrite(LED_BUILTIN, LOW);
    }
}

// ─────────────────────────────────────────────────────────
// Połączenie z WiFi
// ─────────────────────────────────────────────────────────
void connectWiFi() {
    if (WiFi.status() == WL_CONNECTED) return;

    Serial.printf("[WiFi] Łączenie z %s", WIFI_SSID);
    WiFi.mode(WIFI_STA);
    WiFi.begin(WIFI_SSID, WIFI_PASSWORD);

    int attempts = 0;
    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
        if (++attempts > 40) {   // 20 sekund timeout
            Serial.println("\n[WiFi] BŁĄD – restart!");
            ESP.restart();
        }
    }

    Serial.printf("\n[WiFi] Połączono! IP: %s\n",
                  WiFi.localIP().toString().c_str());
}

// ─────────────────────────────────────────────────────────
// Połączenie z brokerem MQTT (z reconnect)
// ─────────────────────────────────────────────────────────
void connectMQTT() {
    while (!mqttClient.connected()) {
        Serial.printf("[MQTT] Łączenie z %s:%d ...\n", MQTT_HOST, MQTT_PORT);

        bool connected = mqttClient.connect(
            MQTT_CLIENT_ID,
            MQTT_USER,
            MQTT_PASSWORD
        );

        if (connected) {
            Serial.println("[MQTT] Połączono z brokerem (TLS) ✓");

            // Subskrybuj topiki po każdym połączeniu
            mqttClient.subscribe(TOPIC_SUB);
            Serial.printf("[MQTT] Subskrybowano: %s\n", TOPIC_SUB);

        } else {
            // Wypisz kod błędu PubSubClient i TLS
            Serial.printf("[MQTT] Błąd połączenia, rc=%d\n",
                          mqttClient.state());
            printTLSError();
            Serial.println("[MQTT] Ponowna próba za 5s...");
            delay(5000);
        }
    }
}

// ─────────────────────────────────────────────────────────
// Diagnostyka błędów TLS
// ─────────────────────────────────────────────────────────
void printTLSError() {
    int err = tlsClient.lastError(nullptr, 0);
    if (err != 0) {
        char errBuf[256];
        tlsClient.lastError(errBuf, sizeof(errBuf));
        Serial.printf("[TLS] Błąd %d: %s\n", err, errBuf);
    }
}

// ─────────────────────────────────────────────────────────
// Odczyt "sensora" – zastąp prawdziwym pomiarem
// ─────────────────────────────────────────────────────────
float readTemperature() {
    // TODO: np. dht.readTemperature() lub ds18b20
    return 21.5f + (random(-10, 10) / 10.0f);   // symulacja
}

// ─────────────────────────────────────────────────────────
// SETUP
// ─────────────────────────────────────────────────────────
void setup() {
    Serial.begin(115200);
    delay(500);
    Serial.println("\n=== ESP32 MQTT TLS ===");

    pinMode(LED_BUILTIN, OUTPUT);

    // 1. WiFi
    connectWiFi();

    // 2. Ustaw certyfikat CA – weryfikacja serwera włączona
    tlsClient.setCACert(CA_CERT);

    // 3. Skonfiguruj MQTT
    mqttClient.setServer(MQTT_HOST, MQTT_PORT);
    mqttClient.setCallback(onMessageReceived);
    mqttClient.setKeepAlive(60);
    mqttClient.setSocketTimeout(15);

    // 4. Połącz z brokerem
    connectMQTT();
}

// ─────────────────────────────────────────────────────────
// LOOP
// ─────────────────────────────────────────────────────────
void loop() {
    // Utrzymuj połączenia
    connectWiFi();
    connectMQTT();
    mqttClient.loop();

    // Publikuj co publishInterval ms
    unsigned long now = millis();
    if (now - lastPublishMs >= publishInterval) {
        lastPublishMs = now;

        float temp = readTemperature();
        char payload[64];
        snprintf(payload, sizeof(payload), "{\"temp\":%.1f,\"uptime\":%lu}",
                 temp, now / 1000);

        bool ok = mqttClient.publish(TOPIC_PUB, payload);
        Serial.printf("[MQTT] Publish %s → %s [%s]\n",
                      TOPIC_PUB, payload, ok ? "OK" : "BŁĄD");
    }
}
